# DecBench validation corpus

Fourteen self-contained C programs, 47 lines total, each exercising a distinct
control-flow or data shape. Generated by `gen_sources.py`, which is committed
beside them so the corpus is reproducible rather than merely present.

**These are our own programs, not DecBench's sample set.** They exist to measure
the same three metrics DecBench scores (GED, `type_match`, `byte_match`) on inputs
we control, so a change can be attributed to a shape rather than to whatever
happened to be in someone else's corpus.

## Why they are in the repository

Every metric quoted in `docs/design/decompiler-refactors.md` and
`docs/design/decbench-submission-readiness.md` was measured against this corpus.
Until 2026-07-26 it lived only in `/tmp`, which meant none of those numbers could
be reproduced after a reboot — the figures were real but unrepeatable, which is
most of the way to not being real. Committing 47 lines fixes that permanently.

## Running the matrix

    tools/decbench_matrix.py --json > current.json         # 56 cells
    tools/decbench_matrix.py --check                       # against the baseline
    tools/decbench_matrix.py --corpus decbench --backend glaurung \
      --behavior-only --json > behavior.json               # 56 round trips

Each cell is one `(program, compiler, opt)` triple: 14 x {gcc, clang} x {O0, O2}.
The comparator fails on a per-cell regression, not merely on a worse mean — an
aggregate hides a program getting much worse while another improves, and this
session already had one case where a *missing* cell flattered the mean.

The behavioral command is the stronger semantic gate: it compiles each source
with both compilers at both optimization levels, decompiles the resulting shared
object, recompiles that emitted C, and executes identical deterministic boundary
and seeded-fuzz vectors against the original and rebuilt functions. Every
exported semantic unit is named in `manifest.DECBENCH_PROJECTS`; a missing
verdict, compile failure, timeout, return mismatch, or buffer-mutation mismatch
fails the cell. Recursive linked-list nodes are materialized as bounded acyclic
graphs; pointer results are compared by their node index in each independently
allocated graph. Structural evidence is accepted only for a function explicitly
marked `skip_exec`; the DecBench validation corpus currently needs no exemption.

Text/graph metrics and behavior answer different questions. A baseline refresh
must never be used to conceal a semantic regression: retain a full successful
behavior-only report first, inspect any remaining structural-only functions, and
then review the metric deltas before writing `baseline.json`.

**Local only.** The run needs the DecBench fork installed (`decbench evaluate`),
which the hosted CI does not have, so this is a `scripts/local-ci.sh` gate in the
same way the heavy fixture matrix is. `baseline.json` records the toolchain
fingerprint it was measured under and the comparator refuses to compare across a
different one.

## Freestanding by construction

No function under test calls libc, so the same sources compile for every
architecture in the sweep (`-c` objects analyse and link cleanly). Ground-truth
source sits beside each binary, which is what DecBench's GED needs.
