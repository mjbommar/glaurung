# Runtime mapping behavior report

> **Kind:** architecture · **Status:** maintained

`src/runtime_analysis/behavior.rs` produces
`glaurung-runtime-mapping-behavior-report-v1` from normalized events in a
validated `ProcessCapsule`. The Python surface is
`glaurung.runtime_analysis.analyze_process_capsule_mapping_behavior`.

The analyzer consumes only provider-neutral `mapping_create`,
`mapping_protect`, and `mapping_remove` events. It never reads raw trace text or
provider-native records. Each mapping lifetime retains process, optional
thread, address, length, creation sequence, initial permissions, ordered
protection-transition indices, and optional removal sequence. Each protection
transition retains its exact prior and resulting permissions.

An initial mapping with both write and execute permission produces an inferred
`writable_executable_mapping` finding. A mapping that was writable and later
becomes executable produces an inferred `writable_to_executable` finding. The
events and permissions remain observations; the security-relevant conclusion
is explicitly inferred. Neither finding claims that bytes executed.

The first implementation deliberately joins events only when process, thread,
start address, and length are identical. A protection or removal of a subrange
is counted as ignored rather than guessed into a lifetime. Mapping-event
completeness is a separate evidence field: observed transitions remain useful
when a stream is partial, but an empty finding set is meaningful only within a
complete declared event scope.

The real fixture gate covers four executions:

- `danger_rw_to_rx.good`: `RW -> unmapped`, no finding;
- `danger_rw_to_rx.bad`: `RW -> RX -> unmapped`, one W-to-X finding;
- `danger_rwx_mapping.good`: `RW -> unmapped`, no finding; and
- `danger_rwx_mapping.bad`: `RWX -> unmapped`, one simultaneous-WX finding.

The semantic-result projection fully satisfies both `danger_rwx_mapping`
oracles. The `danger_rw_to_rx` permission history matches, while execution of
the generated byte remains explicitly unsupported because mapping syscalls do
not observe instruction execution. Mutating a produced permission-history fact
makes oracle evaluation fail.
