published source CFGs and the Java CFGs are both generated by Joern, so their
agreement is evidence of reproducibility, not independent ground truth.

## The 40 apparent Java wins

All 40 have been structurally classified.

### 35: Joern erases infinite loops

Every stored C function in this class contains `while (1)`. Java reports one
entry-and-exit node with no edge. Glaurung reports an entry leading to a loop
node with a self-edge and no exit.

A fresh minimal differential confirms that this is Joern behaviour rather
than a corpus-specific parser failure:

```text
void empty(void) {}
  joern     nodes 1 edges []             roles [(entry, exit)]
  glaurung  nodes 1 edges []             roles [(entry, exit)]

void infinite(void) { while (1) {} }
  joern     nodes 1 edges []             roles [(entry, exit)]
  glaurung  nodes 2 edges [(0,1),(1,1)]  roles [(entry,-),(-,-)]
```

The empty and infinite functions are control-flow-distinct. Joern gives them
the same graph, while Glaurung preserves the reachable non-returning cycle.
Because the published source graph has the same Joern defect, DecBench calls
Java source-isomorphic here. These are explained Java false wins, not
Glaurung defects.

### 3: merge-order entry flags

`rl_complete` once and `bash_dabbrev_expand` twice have identical node count,
edge count, and unlabelled degree multiset between providers. Java marks an
additional block with a predecessor as a function entry. Glaurung marks only
the actual root. This is pyjoern/cfgutils flag propagation during merge, which
depends on NetworkX insertion order; it is not a second semantic entry.

### 2: constant-true loops with reachable breaks

`record_line_starts` and `initbuf` contain `while (1)` loops with reachable
`break`s. Before correction, Glaurung retained a synthetic constant-condition
node and an impossible false edge. The parity layer now proves only bare
nonzero integer literals (and clause-less `for (;;)`), removes only the false
edge, and retains the loop and every real `break` edge.

Node counts now agree with Java: 10 for `record_line_starts`, 5 for `initbuf`.
Java still has two and three extra edges respectively. Direct inspection shows
those are infeasible fall-through edges from a condition that is always true;
matching them would knowingly make the graph less correct.

## Constant-true-loop correction: corpus effect

The complete 85,645-cell rerun changed 2,752 graphs:

- 243 mismatches became exact;
- 16 exact cells became mismatches, including two where Glaurung now matches
  the published source graph isomorphically and Java does not;
- net exact agreement increased by 227, from 81,274 to 81,501;
- uncovered and additional-function counts did not change;
- Glaurung-source-isomorphic differences increased from 92 to 313.

The correction is retained because the removed edges are infeasible by C
semantics. Stored GED movement is reported rather than used as the rule for
acceptance.

## The 1,457 role-only differences

All 1,457 pairs have identical node count, edge count, and unlabelled degree
multiset. The only metric-visible difference is entry/exit flags:

- Java has two or more entries in every case; Glaurung has exactly one;
- 1,441 Java graphs flag at least one node with positive in-degree as an entry;
- the remaining 16 have disconnected syntax-only roots, chiefly repeated
  OpenSSH `log_init` and embedded-switch cases;
- Glaurung flags no positive-in-degree node as an entry.

These are documented Joern merge-order or syntax-component artefacts. Copying
them into Glaurung's general CFG would weaken the meaning of "function entry".
They may be emulated only in an explicitly Joern-compatible scoring view if a
stable rule is recovered; they are not general correctness defects.

## Literal `if` granularity correction

A second fresh differential established that Joern gives a bare literal
`if (0)` or `if (1)` no node of its own. It preserves both CFG arms and moves
the fork to the predecessor; nested literal tests may then collapse because
the NetworkX `DiGraph` deduplicates equal targets. Glaurung now applies exactly
that representation rule in the Joern-compatible projection. It does not
constant-fold to a feasible arm, and it does not change the general CFG.

The focused 23-test node-rewrite module passed. Across all 85,645 cells, 15
graphs changed: 14 mismatches became exact, no exact cell regressed, and one
remaining mismatch moved closer. The fixed cells include all repeated
`dmaGetChannelSpecBy*`, `commanderCrtpCB`, `updateQueuedMeasurements`, and
`ws2812Init` cases, plus `days_to_secs` and `format_checkpoint_string`.

## Remaining graph-size queue

Of 2,334 graph-size differences, 2,289 were touched by the constant-loop
correction. Most now have equal node counts and fewer Glaurung edges because
the infeasible false exits are absent. Only **45** graph-size differences were
unaffected. Fourteen of those are now exact after the literal-`if` granularity
correction. Repeated functions across optimization levels and identical
firmware images reduce the remaining cells to fewer unique source patterns.

### Resolved 9: ternary nested in a loop condition

`flySkySetRcDataFromPayload`, `forwardAuxChannelsToServos`, and
`sumdFrameStatus`, each repeated at O0, O2, and O2-noinline, account for nine of
the 45. Each has a loop condition containing a ternary such as
`i < (x ? 14 : 8)`. Glaurung emitted one extra node and two extra edges.

A fresh minimal differential reproduces the class:

```text
int f(int x, int i) { while (i < (x ? 14 : 8)) i++; return i; }
  joern     4 nodes, 4 edges
  glaurung  5 nodes, 6 edges
```

The trace showed two consecutive branch nodes over the same full-condition
span. The synthetic loop header branches before the nested conditional has
been evaluated, then the conditional branches again. This was a real Glaurung
parity-CFG defect, not a Java flag artefact. A first attempted local deletion
removed the value-only node but left both branch nodes; focused tests rejected
it and the experiment was discarded.

The accepted repair retargets entry and loop-back edges to the real expression
entry and preserves the final branch and every materializing expression,
including a call-bearing ternary arm. Fresh Java differentials for bare, cast,
comparison, load, and call variants are all isomorphic at GED 0.0.

A broader first rule was rejected by the corpus gate because it confused a
ternary at the start of a loop body with one lexically inside the loop test: it
changed 208 graphs, fixed 11 mismatches, and regressed 162 exact cells. Requiring
the ternary span to be contained by the loop-condition span changed exactly the
nine cells above. All nine became exact; no other cell changed. **The remaining
unaffected graph-size queue is 22 cells.**
