# Semantic metrics: past the structural ceiling

> **Kind:** design · **Status:** proposed

## 0. Why this document exists

[`structural-metrics.md`](structural-metrics.md) recommends one structural
metric and says what it cannot do. This is the measurement that bounds the whole
structural family (`mutate.py`, 285 published sample functions, parsed and
mutated with Glaurung's own front end — [`evidence.md`](evidence.md) §8):

```
mutation            applied   CFG isomorphic to the original (defect undetected)
negate-condition        191    191 (100.0%)
constant-bump           174    174 (100.0%)
equality-flip           137    137 (100.0%)
relational-flip         122    121 ( 99.2%)
logic-flip              104     98 ( 94.2%)
arith-flip               67     67 (100.0%)
```

**Six defect classes, 795 injected defects, 7 detected.** No structural metric
can do better on these, because the mutants have the same control-flow graph and
the same control skeleton by construction. A decompiler that inverted every
condition and changed every constant would be, to any structural metric, a
perfect decompiler.

Glaurung has what DecBench does not: one interpreter
([`src/exec/interp.rs`](../../../src/exec/interp.rs), `Machine::run_function`)
running over a `Domain` trait that the concrete emulator and the symbolic engine
both implement, and a `Solver` seam
([`src/symbolic/solver/mod.rs`](../../../src/symbolic/solver/mod.rs)) with a
pure-Rust and a Z3 backend behind it. Stage S5 of
[`../static-c-analysis/roadmap.md`](../static-c-analysis/roadmap.md) calls
bounded equivalence checking "the point". This document argues what the metric
should be, and what it costs.

## 1. The position

**Two tiers, and the cheap one is the headline.**

* **Tier 1 — behavioural agreement.** Lower both the original source function
  and the decompiled function to LLIR (stage S4), run both under
  `Machine<Concrete>` on the same seeded, branch-covering input set, and score
  the fraction of inputs on which the observable outputs agree. Disagreement is a
  *proof* of non-equivalence with a witness. Agreement is evidence.
* **Tier 2 — bounded equivalence.** Only for functions Tier 1 says agree, and
  only to upgrade "agreed on N inputs" to "equivalent under bound B". Reports a
  tri-state; `unknown` is never folded into either side.

Bounded equivalence is not the headline, and this is the one place this document
disagrees with the framing it inherits. A metric whose modal answer is `unknown`
cannot rank thirteen decompilers over 89,014 functions. `unknown` is a
first-class outcome — the sibling workspace enforces that and
[`../static-c-analysis/roadmap.md`](../static-c-analysis/roadmap.md) §7 repeats
it — but a scoreboard column of mostly `unknown` is a report about the solver,
not about the decompiler. Tier 1 always returns a number, and that number is
already a categorically stronger oracle than any structural distance.

## 2. Tier 1, specified

### 2.1 What "the same output" means

The observable of a C function is not just its return value. The comparison is
over a tuple, and each element has to be decided deliberately:

| observable | included | why |
|---|---|---|
| return value, truncated to the declared width | yes | the primary result |
| bytes written through pointer arguments, within the DWARF-declared extent | yes | the second-commonest way a C function communicates |
| the sequence of `(callee, arguments)` pairs | yes | a decompiler that drops a `free()` is wrong even when the return value matches |
| bytes written to globals reachable from the function | yes | same reason |
| execution time, instruction count, register residue | **no** | not observable to a caller; a decompiler is not obliged to reproduce them |
| the order of writes to distinct locations | **no** | over-constrains; C does not promise it |

The call trace is the element most likely to be argued about and the one that
matters most. A decompiler that emits the right arithmetic and loses a
side-effecting call has produced code that is wrong in the way that actually
hurts a reverse engineer, and a pure return-value comparison scores it perfect.

### 2.2 Input generation must be adversarial, not random

This is where a naive implementation fails silently. Random 64-bit inputs take
the `x == 3` branch with probability `2⁻⁶⁴`, so a random-input differential
converges on "everything agrees" and reproduces the structural metric's
uselessness at higher cost. The recorded trap is exact: *"The differential
endorses bad changes — twice it said 'improvements, no regressions' for changes a
census killed"* ([`../../development/traps.md`](../../development/traps.md)).

The input set must be generated by the symbolic engine, not sampled:

1. Run the **source** function once under `Machine<Symbolic>`, collecting path
   constraints to a bounded depth.
2. Solve each collected path constraint for a concrete witness via
   `symbolic::solve(pool, asserts)`.
3. The witnesses are the input set. Every one of them takes a distinct path
   through the *ground truth*, which is the right side to cover — covering the
   decompiled function's paths would let a decompiler that lost a branch pick its
   own easy inputs.
4. Add a fixed set of boundary values (`0`, `1`, `-1`, `INT_MIN`, `INT_MAX`,
   width extremes, and for pointers: null, and an interior pointer) so the metric
   still has inputs when the solver returns `unknown`.

Report `paths_covered / paths_found` with every score. A function whose inputs
covered 3 of 40 paths has a score that means much less than one that covered 38.

### 2.3 The memory-model problem, which is the real cost

A C function that dereferences a `struct` pointer needs an input memory image,
and the image has to be laid out according to a type. The source side gets its
layout from DWARF. **The decompiled side gets its layout from the decompiler's
own type recovery, which is precisely what `type_match` says is usually wrong** —
the best column scores 6,367 of 86,671 (`audited_score.json`).

There is no way around this, only through it, and pretending otherwise is how
a semantic metric becomes a lie. Three honest options, in order of preference:

1. **Score semantics only where the prototypes already agree.** Restrict Tier 1
   to functions whose recovered prototype matches DWARF on arity and on every
   parameter's normalized type — the predicate is already implemented in
   [`src/metrics/type_name.rs`](../../../src/metrics/type_name.rs). The
   denominator becomes small and *decompiler-dependent*, which is a reporting
   hazard: a decompiler with worse type recovery gets scored on an easier
   subpopulation. So the denominator must be fixed once, as the intersection over
   all columns, and published.
2. **Impose the ground-truth layout on both sides.** Build the input image from
   DWARF and hand the same bytes to both functions, ignoring the decompiled
   side's declared types. This measures "given the right memory, does it compute
   the right thing", which is a real and useful question, and it separates
   structural and arithmetic recovery from type recovery instead of conflating
   them. It is wrong for a decompilation whose field offsets differ, and it will
   report those as semantic failures.
3. **Score only scalar-argument functions.** Cleanest, smallest, and the honest
   starting point. What fraction of the corpus that is could not be determined
   offline — it needs the DWARF that the materialized tree does not carry.

**Recommendation: option 2, with option 3 as the first milestone.** Option 2's
bias is nameable and constant across columns; option 1's is neither.

### 2.4 Cost

Not measured, because stage S4 does not exist. What can be said is the shape:
Tier 1 is `N` interpreter runs per function per side, and the interpreter counts
work in `Budget` ticks rather than wall clock. At 32 inputs over 89,014 functions
that is 5.7 M function executions per column per sweep. **This is a nightly, not
an iteration-loop metric**, and the plan in [`roadmap.md`](roadmap.md) treats it
that way: the structural metric stays in the loop, the semantic metric is the
oracle the loop is checked against.

Anyone quoting a cost number here must have run it. Until then this section says
"unmeasured" and nothing else.

## 3. Tier 2, and the discipline it needs

Bounded equivalence: lower both sides to LLIR, execute both under
`Machine<Symbolic>` over a shared `ExprPool`, assert that the observables differ
under equal inputs, and discharge the query with `symbolic::solve`. `unsat` means
equivalent under the bound; `sat` yields a counterexample input; `unknown` is
neither.

Four rules, each of which has already cost something somewhere:

* **A bound is part of the result.** "Equivalent" without "under 8 loop
  unrollings and a 4 KiB memory model" is not a claim. Every number quoted
  carries its bound.
* **`unknown` never becomes a score.** Not a pass, not a failure, not silently
  dropped. It leaves the denominator the way DecBench's non-finite abstention
  does (`decbench/metrics/base.py`), and the `unknown` *rate* is published beside
  the score. A checker that answers `unknown` for everything passes no gate —
  [`../static-c-analysis/roadmap.md`](../static-c-analysis/roadmap.md) §7 already
  says this and it is repeated here because it is the failure mode.
* **The budget must be work, not time.** `DEFAULT_CHECK_TIMEOUT_MS = 250` in
  [`src/symbolic/solver/mod.rs`](../../../src/symbolic/solver/mod.rs) is wall
  clock, and a wall-clock bound makes the score machine-dependent — the same
  input scores differently on a loaded machine. The project has this recorded
  from the fixture side (*"Baseline regen needs a quiet machine"*,
  [`../../development/traps.md`](../../development/traps.md)). A metric-grade
  solver seam needs a **step budget**: solver conflicts, rewrite steps, or
  `Budget` ticks. Wall clock may remain as a safety valve whose expiry is
  reported as an *error*, distinct from `unknown`, and which fails the run rather
  than scoring it.
* **A counterexample must be replayable.** The witness input is stored with the
  cell so a developer can run it. A `sat` with no reproducible input is an
  assertion, not evidence.

## 4. What a semantic metric would have caught

Against the mutation pilot, a correctly-built Tier 1 detects every one of the six
semantics-only classes with a single well-chosen input:

| mutation | inputs needed | why structural metrics miss it |
|---|---|---|
| `negate-condition` (191) | one input on each side of the condition | identical CFG |
| `constant-bump` (174) | one input where the constant is live | identical CFG |
| `equality-flip` (137) | one input satisfying the equality | identical CFG |
| `relational-flip` (121) | one input near the boundary | identical CFG |
| `arith-flip` (67) | almost any non-zero input | identical CFG |
| `logic-flip` (98) | one input where the operands disagree | identical CFG |

The "one input" claim is exactly why §2.2's branch-covering input generation is
load-bearing rather than an optimization: with random inputs the `equality-flip`
row is undetected too, and the semantic metric buys nothing for its cost.

## 5. The stop condition

If, on hand-built known-good and known-bad pairs, Tier 1 cannot separate them —
because the memory model cannot be built, or because branch-covering inputs
cannot be generated for real functions — **the semantic metric is not an oracle
and must not be quoted as one.** Bank the structural work and stop. That is the
same stop condition
[`../static-c-analysis/roadmap.md`](../static-c-analysis/roadmap.md) §7 sets for
S5, and it applies one tier earlier than it was written for.
